01 — THE PODCAST QUESTION, ANSWERED HONESTLY

What we actually know vs what we assumed

✓Facts

  • ~380 Spotify followers on the "Go High Level" show
  • 158 episodes in the catalog; top episode "GoHighLevel Conversation AI Bot"
  • / (the homepage) is your single biggest landing page: 155 sessions/90d
  • The homepage is indexed fine by Google (demotion is page-level by quality, not a domain ban)

✕Assumptions (not proven)

  • That "Direct" traffic (703/90d) comes from the podcast — it's unattributed (typed URLs, bookmarks, AI tools)
  • The only measurable podcast→site traffic is ~28 sessions/90d (clicks from episode notes to /trial/)
  • So "the podcast is the engine" is a guess — and so is "the homepage converts podcast listeners"
The honest call: we can't prove the podcast drives the web traffic, so we don't bet the plan on it. The one hard fact is that the homepage is the most-landed-on page and indexes fine. That makes the homepage the safest concrete first move — it converts whoever arrives, no matter the source. Growing the podcast is a separate bet we can size later with real attribution.
02 — WHAT THE CODE REVIEW CAUGHT (4 must-fixes)

Both models agreed, with line numbers

1

Edit the right file

The live homepage is built inline in build.py (~line 1699). A separate design-homepage.py is dead code — editing it does nothing. We edit build.py and delete the dead file so nobody trips on it again.

2

The Spanish page can't reuse the blog-hub

/es/ is a shared template (also runs /in/, /ar/). We add a dedicated Spanish landing branch so we don't break the others. Its title/text must be real Spanish or the build refuses to ship (there's a guard at line 3209).

3

Don't redirect dead categories to the homepage

301'ing thin pages to / looks like a "soft 404" to Google. We point them at the closest real topic page instead. And we remove the category from the nav completely — the build's link-checker fails if even one link to it is left behind.

4

The build has tripwires — respect them

build.py will refuse to deploy on a broken internal link, a missing tracking tag, or a non-Spanish meta on a Spanish page. Good news: it catches our mistakes before Cloudflare does. We run it locally and confirm it exits clean before pushing.
